# 架構決策紀錄（ADR）說明

本目錄存放 TACTICAL.OS 的架構級決策紀錄（Architecture Decision Record），每個決策獨立成檔，用以記錄限制後續程式碼寫法的架構選擇、理由、放棄的方案、後果與出處證據。

## 什麼時候要寫 ADR

符合以下任一條件時，必須在 `docs/adr/` 新增一份 ADR：

1. 會限制後續程式結構、模組邊界、資料所有權、模擬或渲染規則、或驗證流程的架構級決策。
2. 寫進開案書「契約」章節的架構決策。
3. 推翻或取代既有 ADR 決策時。

產品範圍、素材授權、視覺口味與單次小取捨不拆 ADR，照舊直接記錄於 [DECISIONS.md](../DECISIONS.md)。

## 編號與檔名規則

- 檔名格式為四位數連續編號加英文小寫連字號：`0001-<英文小寫連字號>.md` 起依序遞增（`0001`、`0002`、……），不可跳號或重複。
- 新增 ADR 後，必須在 [DECISIONS.md](../DECISIONS.md) 對應章節留下「一句話摘要＋相對連結」（格式為 `adr/<檔名>`），由 `tests/AdrIndex.test.ts` 驗證索引與檔案雙向一致。

## 推翻既有決策的規則

推翻既有 ADR 時，不可修改原檔的決定內容，必須新開一份 ADR 並雙向標註：

1. 舊檔的狀態行改為 `狀態：已取代（由 <新四位數編號>）`。
2. 新檔在 `日期：` 下一行補上 `取代：<舊四位數編號>`。
3. 新舊兩份檔案皆保留於 `docs/adr/` 目錄與 [DECISIONS.md](../DECISIONS.md) 索引中，由 `tests/AdrIndex.test.ts` 檢查雙向對應。

只修訂既有 ADR 的其中一條、其餘各條仍然有效時（2026-11-28，使用者授權主代理決定；先例 0030、0031 修訂 0029）：新開一份 ADR、狀態寫採用、不填 `取代：`；「決定」第一條寫明修訂哪一份的哪一條，「放棄的做法」寫明為什麼不把舊檔整份標成已取代。舊檔原文與狀態都不動，讀舊檔的人從 DECISIONS.md 同一節緊接著的索引看到修訂。

## 格式與撰寫規範

- 首行標題格式：`# <四位數編號> <繁體中文標題>`（與檔名編號一致）。
- 狀態行只允許三種寫法：`狀態：採用`、`狀態：提議`、`狀態：已取代（由 NNNN）`。
- 僅取代別份 ADR 時才填寫 `取代：NNNN`。
- 必須包含五個章節標題：`## 背景`、`## 決定`、`## 放棄的做法`、`## 後果`、`## 證據`。
- 每份篇幅控制在 20～50 行，使用繁體中文，只寫事實與理由，不寫效果形容詞。
- 原紀錄查不到的欄位（例如未記載曾考慮的替代方案）填寫「原紀錄沒有寫。」，不可自行補編。
- `## 證據` 只列 repo 內真實存在的檔案路徑（由 `tests/DocDrift.test.ts` 與 `tools/adr/check-adr.mjs` 檢查；後者由 `tests/AdrIndex.test.ts` 呼叫，正本在全域 `adr` skill）、WORKLOG 節次、設計文件章節或 commit SHA。

### 範本

```markdown
# 0007 標題（與檔名編號一致）

狀態：採用
日期：2026-11-17
取代：0003

## 背景

說明觸發此決策的問題、限制或量測數據。

## 決定

說明實際採行的規則、邊界、唯一寫入者或實作落點。

## 放棄的做法

說明曾評估但未採納的方案與原因；原紀錄未記載時寫「原紀錄沒有寫。」。

## 後果

說明遵循此決定帶來的保證、測試守門與對應代價。

## 證據

- 列出處文件、程式路徑、測試檔案或 commit SHA。
```
