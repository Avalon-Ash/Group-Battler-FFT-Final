## 3. 設計規則

### 差異化的判定

每招定義五項：主剪影、空間構圖、運動方向、節奏、收尾痕跡。與最相似招式比較時，至少兩項有實質差異，其中至少一項為剪影或運動；不能以換色達標。

同職業五招必須並排比較；全 50 招再作一次跨職業檢查。允許共用烘焙零件，但不強迫每招使用不同 kind，也不設定柱體使用配額。需要城牆才做城牆，需要刀刃才做刀刃。

保留六角世界、陣營紋章與色階語言。兵器、裂隙、冰峰、月體等以六角結構與切面構成，不把六角世界簡化成每招一根六角柱。

### 詠唱與命中

- 第一版將所有低於 1.5 秒的奧義提高到 1.5 秒，保留現有 2.0 秒的穿日神矢。先不額外拉長其他招式。
- 1.5 秒是施法入口的有效下限；預設資料、技能編輯入口與執行期使用同一規則，UI 顯示與事件排程必須一致。不得只在 timer 私下 clamp 造成讀條／特效仍沿用舊值。
- 從開始詠唱即給辨識訊號；中段具象主體逐漸成形；末段呈現明確蓄力峰值；成功結算時才出現主爆發。
- 持續讀條與局部蓄力不等於全程大面積遮擋。主爆發及濃重遮擋維持短暫；持續狀態由既有狀態視覺承接。
- 命中必須對齊真實傷害／治療／效果事件。動畫的多片刀光、雨滴或裂紋不能被誤當作額外傷害次數。
- 被暈眩、恐懼、沉默、放逐、死亡等現有中斷條件打斷後，取消待播放主爆發，收掉詠唱主體與預警；重置戰場也不得留下延遲特效。
- 目標移動、死亡或離場時，預警、演出中心與實際結算須遵守同一目標規則，避免長詠唱放大既有偏差。
- 不新增全畫面閃白、頻繁暗場或頂部喊招橫幅。

## 6. 測試與預算策略

- 更新主爆發辨識，使具象兵器、裂地、狀態封存等可作為命中主體；以時序資料明確標示，不能只靠最大 glow/ring 推測。
- 不使用 skill.target 這個不存在的欄位；依實際技能功能與既有判定建立傷害、控場、治療、增益的驗收分類，混合技能需明確定義。
- 先維持既有粒子與效能預算，透過烘焙複合零件提高造型密度；不照搬舊草案的 110 顆粒子與 10 層全面放寬。
- 新的必要上限變更須附局部理由與壓力量測，不能靠放寬門檻掩蓋回歸。新增時序測試覆蓋 1.5 秒下限、編輯後技能、中斷、死亡、重置與不同 dt。
- 差異化不靠檢查零件種類數量宣稱成功：看詠唱中段、命中幀、命中後 0.15 秒、餘韻四個階段的並排組圖，補短動畫／實戰驗證動態。
- 戰場同時施放時保留單位、血條、範圍預警可讀性；非主體的共用命中包退為陪襯。
- 改位置／高度／排序時同步 RenderSpec 與檔頭，跑 verify:coords；粒子、尺寸、色階集中在 constants 或 data profiles。
- 預期中的戰鬥畫面變動仍先保存 old/new/diff，確認差異原因與未受影響場景後另列基準更新事項；本計畫不預先授權重錄或放寬既有基準。

## 7. 最終平衡方案

不在每批美術完成後重跑大量平衡模擬；待施法與 50 招演出完成，鎖定一個 commit 才開始。

1. 初次量測：相同種子的 1,000 場一般站位＋1,000 場交換站位。
2. 保留既有六項指標作比較：站位與合併勝率、戰鬥時長、逾時、高頻技能勝率差、職業紅藍差；詠唱變長可能改變戰鬥時長，目標若需調整，必須給設計理由，不為過關臨時改門檻。
3. 加記奧義詠唱開始數、成功施放數、中斷率、死亡取消率、首次成功施放時間，以及各招傷害／治療／控場貢獻。補工具觀測能力時不改模擬規則。
4. 發現偏差再調傷害、治療、護盾、消耗、CD／控制持續等適當欄位；不得把 cast 降回 1.5 秒以下救勝率，也不得偷偷加免控確保放得出來。
5. 調整定稿後，以另一組固定種子再跑 1,000＋1,000 場驗證，避免只針對調參樣本改善。若初次結果無需調參，也保留第二組作獨立確認。
6. 每次報告明記 commit、種子、場次、步長、站位；既有 BT 報告只保留歷史用途。

## 8. 部署及實機安排

- 最終準備固定種子的實機案例：高低差突進與近戰前衝、輔助治療後接敵方普攻、PBAOE 範圍判斷、滿血不空補，以及 1.5 秒奧義的預警與中斷。
