## 3. 坦克最小實測

1. **安裝與生成。** 未來實測時，解壓官方 **ComfyUI Windows NVIDIA Portable**，用它自帶的 Python，系統的 Python 3.10 可照常用。選已包含 3D 原生節點的版本，開啟本機模板 `Pixal3D & TRELLIS.2: Image to Model`。依模板放兩份 INT8 checkpoint、共用 Shape／Texture VAE、DINOv3、MoGe 和 BiRefNet。用自己有權使用的全身 A-pose 概念圖，讓手臂離開腰、雙腳分開，盾和武器留給 Blender。從 **5 萬三角面、1K 貼圖**開始，必要時再降低 remesh 解析度或 UV 前的目標面數。這兩個數字是實測起點。 [Portable 安裝](https://github.com/Comfy-Org/ComfyUI/blob/master/docs/installation.md#windows-portable) · [模板和模型路徑](https://docs.comfy.org/tutorials/3d/pixal3d) · [UV 顯存問題](https://github.com/Comfy-Org/ComfyUI/issues/16056)
2. **先出第一張烘焙圖。** 在現有坦克烘焙場景的副本匯入 GLB，套現有 toon 材質做法並接上 Base Color。沿用 **30° 正交鏡頭、腳底錨點、光線與描邊**，先烘 SE／NE 各一張，和原坦克在 **64 px、130 px** 並排，看頭盔、肩甲、盾與短腿是否清楚。現有腳本固定載入 `Knight.glb`、尋找 `Rig`、按名稱隱藏網格，所以首張從場景副本手動換網格最快。正式批烘需讓離線試作入口接受新網格。 [烘焙 README](C:/Git/Group-Battler-FFT-Final/tools/assets/blender/README.md:19) · [載入與網格過濾](C:/Git/Group-Battler-FFT-Final/tools/assets/blender/render_unit.py:104) · [材質轉換](C:/Git/Group-Battler-FFT-Final/tools/assets/blender/render_unit.py:118)
3. **再驗證動作。** 先轉權重並檢查 `walk` 的腳底、`attack` 的肩甲與手腕，再驗 `idle`、`hit`、`death`。目前坦克只映射這五組。第六組先從 CC0 KayKit 挑 `Spellcasting` 當試作候選，在同骨架確認盾手和頭盔姿勢，再加到試作的 `cast` 映射。最後用四向烘焙檢查整組輪廓和腳底定位。 [現有坦克映射](C:/Git/Group-Battler-FFT-Final/tools/assets/blender/render_unit.py:60) · [四向取樣](C:/Git/Group-Battler-FFT-Final/tools/assets/blender/render_unit.py:273) · [KayKit 動作包](https://kaylousberg.com/game-assets/character-animations)

**時間估算。** 概念圖、權重和坦克烘焙場景都到位後，預留 **30–60 分鐘出首張可比較的靜態圖**，約 **1.5–3 小時出能檢查 `walk`／`attack` 的版本**。首次取得權重的時間另計。六組動作是否能在同一個工作段完成，主要取決於腋下、胯下與肩甲要不要拆件或重拓樸。

**備案。** 在同一套本機 ComfyUI 模板切換到 **TRELLIS.2 INT8**，用同一張圖、相同面數和貼圖設定再跑一次，Blender 端沿用同一場景和骨架。兩者共用匯出節點，若卡在 `UnwrapMesh`，先降面數。若 Pixal3D 已出圖但背面輪廓有問題，而且手上有一致的正、側、背圖，再試 Pixal3D 的四視角路線。 [共用模板](https://comfy.org/hub/workflows/pixal3d-trellis-2-image-to-model-920c795f693a/) · [四視角工作流](https://docs.comfy.org/tutorials/3d/pixal3d) · [低顯存四視角實測](https://github.com/Quentincls/localmesh-engine#measured-times)
